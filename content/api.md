## ひとことで

プログラムが別のプログラムに用事を頼むための、決まった形の窓口です。

## なぜ大事?

いまのアプリは、1社だけで作られていません。地図はGoogle、決済はクレジットカード会社、AIの応答はOpenAIやAnthropic。それぞれの会社のプログラムを呼び出して、1つのサービスに組み上げています。この呼び出し口がAPIです。

APIがあるおかげで、中身を知らなくても他人の技術を使えます。地図の描画アルゴリズムを理解していなくても、地図を表示できる。これが、少人数でも本格的なサービスを作れる理由です。

AIかけこみ寺の道具立てもここに乗っています。生成AIをプログラムから呼ぶのもAPI、メンバー限定サイトがデータベースから出席記録を取るのもAPIです。APIという概念を1つ覚えると、「なぜ個人でもアプリが作れる時代になったのか」の答えが半分わかります。

## やさしい解説

APIは、レストランの注文窓口だと思ってください。

客は厨房に入りません。メニューを見て、決まった料理名を伝えるだけです。厨房が何人で回っていようが、コンロがガスか電気かは客に関係ありません。逆に、メニューにない料理は頼めませんし、「塩少なめ」のような注文もメニューに書かれた形でしか受け付けられません。

この、メニューにあたるものがAPIの仕様書です。何を頼めるか、どう書いて頼むか、どんな形で返ってくるかが書かれています。GitHubの公式ドキュメントも、OpenAIの公式ドキュメントも、中身はこのメニュー表です。

実際の呼び出しは、URLへのアクセスに似た形をとります。よく使われるのがREST APIという方式です。たとえばGitHubに「このユーザーの情報をください」と頼むときは、こういうURLにアクセスします。

```
GET https://api.github.com/users/octocat
```

返ってくるのは、人間向けのページではなく、機械が読みやすいJSONという形式のデータです。

```json
{
  "login": "octocat",
  "name": "The Octocat",
  "public_repos": 8
}
```

このデータをプログラムが受け取り、自分のアプリの画面に並べ直します。ホームページを人間が読むのがブラウザ、APIを機械が読むのがプログラム、という関係です。

ここで必ず出てくるのが認証です。誰でも無制限に呼べると、悪用もされますし、料金の請求先もわかりません。そこでAPIキーやトークンと呼ばれる合言葉を一緒に送ります。この合言葉は、絶対に他人に見せてはいけません。公開のリポジトリにうっかり書き込んでしまい、他人に使われて高額な請求が来る、というのはよくある事故です。

注意点をもう1つ。APIは提供する側の都合で仕様が変わったり、終了したりします。他社のAPIに深く依存したサービスを作るときは、止まった場合にどうするかまで考えておく必要があります。
