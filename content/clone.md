## ひとことで

サーバーにあるリポジトリを、履歴ごと丸ごと自分のパソコンに複製する操作です。

## なぜ大事?

Gitでの作業は、クローンから始まります。参加したいプロジェクトがあれば、まず手元に複製を作る。ここが入口です。

複製されるのは、いまのファイルだけではありません。過去の全履歴が付いてきます。だから、ネットにつながっていない場所でも、過去の版を見たり、変更を記録したりできます。オープンソースが世界中の人の協力で成り立っているのは、この「まず手元にまるごと持ってこられる」性質があるからです。

AIかけこみ寺でも、新しく開発に加わるメンバーの最初の作業はクローンです。共有ドライブでファイルを受け渡すのではなく、GitHubから各自のパソコンにクローンする。これが共同開発の出発点になります。

## やさしい解説

クローンは、図書館の本を借りるのではなく、全ページと改訂履歴つきで完全な複製をもらう、という感覚に近いです。

借りた本なら、書き込めませんし、返さなければなりません。クローンでもらった複製は、自由に書き換えられます。しかも、元の本とのつながり（どこから来たか）を覚えているので、元の本が改訂されたときに差分だけ取り寄せることもできます。

操作は1行です。

```bash
git clone https://github.com/ai-kakekomi/wiki.git
```

これで、`wiki` という名前のフォルダができ、中にファイルと `.git` という履歴の入った隠しフォルダが入ります。フォルダ名を変えたいときは、うしろに書き足します。

```bash
git clone https://github.com/ai-kakekomi/wiki.git my-wiki
```

公式ドキュメントによれば、クローンをすると次のことが自動的に行われます。元のリポジトリの各ブランチに対応する追跡用の枝が作られ、既定のブランチが取り出され、複製元のアドレスが `origin` という名前で登録されます。この `origin` があるおかげで、あとから `git pull` や `git push` の相手先をいちいち指定せずに済みます。

似た言葉との区別をしておきます。

- クローン：他人または自分のリポジトリを、自分のパソコンに複製する
- フォーク：他人のリポジトリを、GitHub上の自分のアカウントに複製する
- プル：すでに手元にある複製を、最新に更新する

他人のプロジェクトに変更を提案したい場合は、まずフォークし、そのフォークをクローンする、という順番になります。

注意点を2つ。第1に、履歴を全部持ってくるので、大きなプロジェクトでは時間と容量がかかります。最新だけでよければ `--depth=1` を付けると軽くなります。第2に、クローンした先には元のリポジトリのアドレスが記録されています。そのままでは元に書き戻す権限はありませんが、うっかり公開リポジトリにプッシュしてしまう事故を避けるため、自分がどこに向かって作業しているかは把握しておいてください。
