Git

Gitギット分散型バージョン管理システム

上級 プログラミング

ひとことで

ファイルの変更履歴を記録し、いつでも過去に戻れるようにする道具です。世界の開発現場のほぼ標準です。

なぜ大事?

1人で作業していても、「昨日の状態に戻したい」は必ず起きます。複数人になると、もっと切実です。2人が同じファイルを別々に直したとき、あとから保存した人の内容だけが残って、もう片方の作業が消える。共有フォルダで作業した人なら経験があるはずです。

Gitは、この事故を構造的に防ぎます。誰の変更も履歴として全部残り、衝突した箇所だけを人間に確認させます。消えないことが保証されるので、思い切って試せるようになります。

AIかけこみ寺では、代表と協力メンバーが別々のパソコンから、LPやメンバー限定サイトを触っています。Gitがなければ、この分担は成り立ちません。ちなみに、リポジトリを共有ドライブに置くとGitの履歴が正しく同期できず事故になるため、各自のパソコンのローカルに置く運用にしています。

やさしい解説

Gitは、ゲームのセーブ機能に似ています。

強敵に挑む前にセーブしておけば、負けても直前からやり直せます。しかもGitのセーブは1本ではなく無限に作れて、それぞれに「なぜここでセーブしたか」のメモが付きます。さらに、別ルートを試すための分岐（ブランチ）まで作れます。失敗しても本編に影響しません。

Pro Gitという公式の教科書では、Gitの特徴として次の点が挙げられています。データを差分ではなくスナップショット（そのときの全体像）として持つこと。ほとんどの操作が手元だけで完結するので速いこと。保存するものすべてにハッシュという指紋を付けるので、中身がこっそり変わればすぐわかること。

作業の流れは、3つの場所を行き来する形で覚えます。

  1. 作業ツリー：いま編集しているファイルそのもの
  2. ステージ：次の記録に含めるものを並べておく台
  3. リポジトリ：記録が確定して保管される場所

コマンドにすると、こうなります。

git status            # いま何が変わっているか確認する
git add 記事.md        # 記録したいファイルを台に載せる
git commit -m "記事を追加"  # 台の上のものを履歴として確定する
git log               # これまでの履歴を見る

「分散型」というのは、全員が履歴の完全な複製を持っている、という意味です。中央のサーバーが壊れても、誰か1人の手元があれば全部復元できます。これが、昔の中央集中型のバージョン管理との大きなちがいです。

GitとGitHubは別物です。Gitは手元で動く道具、GitHubはそのリポジトリを預かって共同作業しやすくするWebサービスです。GitHubを使わずにGitだけ使うこともできます。

注意点を1つ。Gitは強力なぶん、履歴を書き換える操作（rebaseやforce push）もできます。ここで手を滑らせると、他人の作業を消してしまうことがあります。慣れないうちは、追加していくだけの操作（add、commit、push、pull）に絞るのが安全です。
